# 数据字典：第一版只需要这些数据

| 字段 | 人话解释 | 用途 |
| --- | --- | --- |
| `gmv` | 成交总金额 | 判断生意规模和变化 |
| `visitors` | 进店/进入页面的人数 | 判断流量是否变化 |
| `paying_customers` | 最终下单的人数 | 判断成交规模 |
| `payment_conversion_rate` | 下单人数 ÷ 访客人数 | 判断流量有没有变成订单 |
| `repeat_purchase_rate` | 再次购买的顾客占比 | 判断顾客是否愿意回来 |
| `delivery_rating` | 外卖平均评分 | 判断服务体验 |
| `avg_wait_minutes` | 平均等待分钟数 | 用来解释差评、转化下降等问题 |

## 我们的第一条“经营逻辑”

如果午高峰的访客数增加，但支付转化率明显下降，同时平均等待时间变长，那么优先判断为：高峰期出餐能力不足，导致顾客流失。

这不是 AI 凭空猜的结论，而是“数据事实 + 业务规则 + AI 解释”的组合。这正是项目未来最值得在面试中讲清楚的部分。
